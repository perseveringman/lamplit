> **这份文档定的是产品逻辑，不定实现逻辑。**

## 1. 产品定位

把新概念英语 1–4 共 288 篇课文，编织成一张**可点可查可学**的知识网。学习者不再"按书号顺序背课文"，而是：
- 从一个**知识点**出发，看到它在哪些课文里出现、怎么用、和谁相关
- 从一篇**课文**出发，看到它承载哪些知识、能用在什么场景
- 从一个**能力目标**（如"能在公共场合礼貌求助"）出发，按簇串起相关课文

最终落到一个**阅读工作台**：在这里把一篇课文真正读完，所有注解都铺在原文上。

**面向谁**：英语中级学习者，已经有基础语法与词汇，想要**系统化、可追溯**地精读 288 课。

---

## 2. 核心体验循环

```
      ┌──────────────┐
      ↓              │
  打开一篇课文        │
      │              │
      ↓              │
  阅读工作台          │
  (读 + 看注解)      │
      │              │
      ↓              │
  遇到不懂的 KP      │
      │              │
      ↓              │
  跳转知识详情        │
      │              │
      ↓              │
  看到所有相关课文 ───┘
      │
      ↓
  按能力簇继续学下一组
```

整个产品服务于这个循环：**课文是锚点，KP 是脉络，能力簇是关卡。**

---

## 3. 信息架构

系统中流转的核心实体（**仅概念层面，具体字段由实现者决定**）：

| 实体 | 一句话定义 |
|---|---|
| **课文**（288 个）| 一个学习单元，含标题、原文、知识总结、可选能力标签 |
| **知识点 / KP**（约 4000+）| 课文中可被点亮的语言单位，分 4 类：词 / 语块 / 句型 / 语法 |
| **能力簇**（约 25 个）| 学习者视角的"学完能用英语做什么"，把多篇课文串成一段学习路径 |
| **句子**（约 4400 句）| 课文中的每一句，按学习价值分为 3 档：范句 / 长难句 / 例句 |
| **关联** | 实体之间的关系：KP 出自课文、KP 包含词、句型从属语法、同课 KP 共现、课文间共点 |

**重要设计原则**：
- KP 名称应保留中文（如"一般过去时"、"礼貌求助"），便于学习者检索
- 句子的"档位"是阅读工作台的视觉信号，但同一句也是 KP 出现的语境
- 能力簇不是预定义目录的"分类法"，而是**学完能用英语做什么**（即"Can-do"）的视角

## 4. 五个视图

每个视图只回答一个核心问题：

| 视图 | 核心问题 | 用户行为 |
|---|---|---|
| **星图** | 这个 KP 和谁相关？ | 看到一个节点，点开看邻域；可拖可缩放 |
| **列表** | 全集有多少 KP？按什么维度浏览？ | 翻页、过滤、排序、点开看详情 |
| **连学** | 想达成某个能力，要读哪些课文？ | 选能力簇，看簇内课文卡片，挑感兴趣的精读 |
| **课文共点** | 哪几篇课文用了同一批 KP？ | 看共享度高的课文对，按 KP 路径跳转 |
| **阅读工作台** | 这一课到底在讲什么？ | 真正读完一篇，每一行都有注解 |

四个"导航类"视图 + 一个"落地类"视图。星图/列表是查，连学是路径，课文共点是发现关联，**阅读工作台是阅读本身**。

## 5. 各视图的产品逻辑

### 5.1 星图

**目的**：以一个 KP 为圆心，看到它在知识网里的局部邻域。

**行为**：
- 打开页面时，自动定位一个"枢纽节点"——一个**贯穿多课、高关联度**的语法点（如"一般过去时"），让用户第一眼就看到最有用的内容
- 节点按类型上色（4 种 + 课文 1 种）
- 节点之间的距离 / 排布，应让"中心节点 + 同课 KP"一眼可读
- 单击任一节点 = 切到该节点的邻域图
- 边代表关系；视觉上应区分"包含关系"（实线）和"共现关系"（虚线）
- 用户可拖动、缩放，不迷路（缩回全图的能力要有）

**节点类型与颜色**（建议语义，不锁色号）：
- 词 = 偏冷色调（青绿）
- 语块 = 蓝色系
- 句型 = 紫色系
- 语法 = 暖色（橙黄）
- 课文 = 橙色

**该视图不做什么**：
- 不展示 4000+ 节点（必须聚焦）
- 不展示课文正文
- 不做修改/编辑

### 5.2 列表

**目的**：全集浏览。当用户想要"看看都有什么"或"按某个维度筛选"时使用。

**行为**：
- 默认显示全部 KP，可按类型过滤
- 支持按多种维度排序（关联度、出现课数、名称、类型）
- 课文始终按册课序排（不论选哪种排序方式）
- 分页（每页约 80 条）
- 句子作为"虚拟类型"也能进入列表：分范句 / 长难句 / 例句池 三档
- 单击任一项 = 跳转到详情

**该视图不做什么**：
- 不做图（这是文本浏览）
- 不展示图结构关系

### 5.3 连学

**目的**：把 288 课按 25 个能力簇组织，让用户**有路径可走**而不是"漫无目的挑课"。

**行为**：
- 左栏列出 25 个能力簇，按包含课文数降序
- 每个簇有一个"can-do"短句（学完能做什么）
- 选中一个簇，右栏展示该簇下的课文卡片
- 卡片包含：课号 / 体裁 / 场景 / can-do / 知识胶囊（语法1 + 句型1 + 语块2 + 主簇标签）
- 单击卡片 = 进入该课详情（不是直接进阅读工作台——先让用户看到画像）
- 支持"全部课文"入口，按册课序浏览

**该视图的判断**：
- 簇顺序应**有逻辑**（生存 → 日常 → 叙事 → 读写 → 思辨），不能随机
- 能力簇命名用中文动作短语（"能在公共场合礼貌求助"），不是分类名词

### 5.4 课文共点

**目的**：发现"用了同一批 KP 的课文对"，让用户意识到"这两篇可以一起学"。

**行为**：
- 列出共享 KP 数最多的 100 对课文
- 每对显示：A 课 / B 课 / 共点数 / 通过哪些 KP（共点 pill）
- 单击 KP pill = 跳到该 KP 详情
- 单击课文 = 跳到该课详情

**该视图的判断**：
- 共点 ≥ 3 的才有展示价值
- 应通过 pill 透出"是因为这些 KP 共点"，而不是只显示数字

### 5.5 阅读工作台（核心新增）

**目的**：把"知识网"反过来铺回课文中，**让用户真正读完一篇**。

**这是整套应用的着陆点**——前面所有视图都是为这一刻服务。

#### 布局（三栏）

```
┌────────────────────────────────────────────┐
│  顶部：标题 + 课间导航 + 层开关              │
├──────────┬──────────────────┬─────────────┤
│ 知识胶囊  │ 课文全文           │ 当前句详情   │
│ (左)     │ (中，每行 = 一句)   │ (右)        │
└──────────┴──────────────────┴─────────────┘
```

#### 顶部
- 品牌 + 课号课名
- 课间导航（前一篇 / 后一篇，按册课序）
- 层开关（详见下文）

#### 左栏：知识胶囊
- 按 KP 类型分 4 组：语法 / 句型 / 语块 / 词
- 每组是该课出现的 KP 摘要
- 单击胶囊 = 在课文中**定位并高亮所有该 KP 出现处**
- 胶囊可标"⭐ 重点学"（用户状态）

#### 中栏：课文全文（核心）
**这是阅读工作台的灵魂。**

- 每一行 = 一句（按句渲染，不打散）
- 每一句有**左侧标记条**：范句紫色实线 / 长难句橙色虚线
- 句中按多个层级叠加高亮（详见下文"高亮层级"）
- 单击任一句 = 在右栏打开该句详情

**高亮层级**（默认哪些开、哪些关由实现者决定，但语义如下）：

| 层 | 内容 | 默认 | 理由 |
|---|---|---|---|
| 句型层 | 范句整句左竖条 / 长难句整句左竖条 | 开 | 必须一眼看到"这是范句还是长难句" |
| 语法层 | 该课语法点在句中的命中 | 开 | 用户提到的核心 |
| 语块层 | 该课语块在句中的命中 | 开 | 比单词更可迁移 |
| 词层 | 单词（区分新词 vs 已学） | 关 | 新手不要被高亮淹没 |
| 衔接层 | 衔接词（because/however/then 等）| 关 | 课文之所以是课文，靠它们黏合 |
| 体裁层 | 顶部一条 ribbon（对话/叙事/议论/说明）| 开 | 决定阅读策略 |

**关键判断**：
- 默认**只开 3–4 层**，其他做成开关（避免视觉噪音劝退新手）
- 范句 / 长难句的标记**比颜色更重要**——颜色是"看"，左竖条是"停下来"
- 用户标过"⭐"或"⚠️ 不会"的 KP，应在课文中**最显眼**

#### 右栏：当前句详情
- 顶部：句文本（大字）+ 元数据（所属课 / wc / 从句数 / 层级）
- 段"为什么值得学"：按层级给固定文案
  - 范句：建议整句记忆并替换成分操练
  - 长难句：先抓主干再剥修饰，对照语法点拆解
  - 例句：作词 / 语块 / 句型的上下文，不必背诵
- 段"句中知识点"：列出该句包含的所有 KP
- 段"回到课文"：固定跳板

#### 用户状态（轻量）
- 用户可标"⭐ 重点学"和"⚠️ 不会"
- 状态本地保存（不依赖账号）
- 后续可基于此做"只看我弱的"过滤、SRS 复习等（不在本规约范围）

#### 阅读工作台不做什么
- 不做翻译（用现成中文注解）
- 不做语音评测
- 不做笔记功能（先观察是否真的需要）
- 不强求用户读完打卡（学习节奏由用户定）

## 6. 关键交互（跨视图通用）

### 6.1 选中 → 联动
任何视图里选中一个 KP / 句子 / 课文，其他视图应该能**跳转或联动**：
- 单击 KP → 打开详情卡 + 星图跳到该 KP 邻域
- 单击课文 → 打开详情卡 + 可跳到阅读工作台
- 单击句子 → 打开详情卡 + 关联到阅读工作台原文位置
- 单击能力簇 → 跳到连学模式

### 6.2 搜索
- 顶部搜索框 = 模糊匹配 KP 名称
- 命中优先级：完全匹配 > 前缀 > 包含 > 释义包含
- 搜索出 KP 后，单击进入详情
- 搜索不止于 KP，应该能搜到句子、课文（具体取舍由实现者决定）

### 6.3 详情卡（通用）
选中任一实体，右侧或某固定位置出现一张详情卡：
- 标题 + 类型 + 出处
- 在哪些课文里出现过（按册课序）
- 它从属什么 / 包含什么 / 关联什么
- 关联条目均可点击跳转

**详情的逻辑**：
- 课文详情 = scene + can-do + 簇归属 + 知识总结 + 本课 KP + 相邻课文
- KP 详情 = 名称 + 类型 + 释义 + 出现课文 + 关联 KP（按类型优先级排序）
- 句子详情 = 层级 + 出处 + 句中 KP + 跳回原文

## 7. 视觉语言

只定**调性**，不定具体值：

- **暗色主题**：深蓝底 + 米色详情卡片 + 暖金强调色——参考"夜晚在灯下读书"的氛围
- **节点类型用色相区分**（不要用形状/大小区分，颜色是用户最敏感的信号）
- **字体分层**：标题用衬线（宋体），正文用无衬线（苹方），编号用等宽
- **不滥用动画**：只在"选中"和"定位"时有微动效
- **响应式**：见 §11 多设备策略

实现者应自行设计具体色号、字体栈、间距尺度。

## 11. 多设备策略

应用必须在 **手机 / 平板 / PC** 三种形态下都能完成核心任务。

### 11.1 核心判断

**所有形态必须能用的功能**：
- 阅读工作台（核心任务）
- 搜索
- 选中 → 详情（任意实体都能看到自己的信息）

**只在 PC / Pad 上提供的功能**：
- 星图（触屏拖拽体验差，下面有替代）
- 课间导航之外的多维筛选
- 大屏特有的并排对比

### 11.2 形态定义（参考阈值，实现者可调）

| 形态 | 视口宽度 | 主要交互 | 布局策略 |
|---|---|---|---|
| **PC** | ≥ 1024 px | 鼠标 + 键盘 | 三栏 / 多栏 |
| **Pad** | 640–1023 px | 触摸 + 偶尔键盘 | 两栏 + 抽屉 |
| **手机** | < 640 px | 触摸为主 | 单栏堆叠 + 抽屉 |

### 11.3 各视图的多设备行为

#### 阅读工作台（必须三态都好）
- PC：三栏（左胶囊 / 中全文 / 右详情）
- Pad：两栏（左胶囊 + 中全文）；句详情变成底部抽屉（向上滑出）
- 手机：单栏堆叠；胶囊默认收起（顶一个按钮展开）；句详情变成全屏 sheet

**底线**：手机用户**必须能读完一篇课文**，必须能看到高亮。

#### 星图
- PC：完整图，鼠标拖拽 + 滚轮缩放
- Pad：保留图，但**支持双指缩放 / 单指拖动**
- 手机：**不展示完整图**（触屏体验差），改为：
  - 顶替成"邻域列表"（中心节点 + 邻居按类型分组的列表）
  - 或保留图但**锁死中心节点**，禁止拖拽，只允许点节点切换
  - 实现者自选，但**不能直接砍掉"图"这个视图**，必须有个等效入口

#### 列表 / 连学 / 课文共点
- 这三个是文字为主，三态都好
- 区别仅在：
  - 表格列数随宽度变（窄屏折叠次要列）
  - 卡片网格 column min-width 自适应

#### 详情卡
- PC / Pad：右栏固定
- 手机：变成全屏 sheet 或底部抽屉，**不能挤掉阅读工作台的正文**

### 11.4 触摸特有

- **没有 hover**：所有 hover 揭示的内容必须有 tap 等价
  - KP 详情展开、tooltip、辅助说明——点击或长按触发
- **长按 = 等效 hover**（300–500ms）是一种方案
- 按钮 / 胶囊的点击区域**至少 44×44 px**（iOS HIG），不要让用户瞎点

### 11.5 性能底线

- 移动端首屏 < 3 秒（4G）
- 阅读工作台翻课 < 1 秒（已加载过）
- 不要在手机上跑力导向布局计算（星图若在手机上保留图，必须降级算法）

### 11.6 验收补充

在原 §9 验收基础上，多设备要满足：

1. iPhone SE 视口（375×667）打开阅读工作台，能读完一篇且看到高亮
2. iPad 视口（768×1024）打开星图能双指缩放
3. PC 视口（1280×800）三栏同时可见
4. 任一设备下，点击 KP 都能进入详情
5. 阅读工作台的手机模式下，句详情不能盖住全文的下一句（要么 sheet，要么展开式）
6. 横竖屏切换不崩（至少不丢失状态）

## 12. 复习功能与知识卡片

### 12.1 一句话定位

应用里**任何可点的实体**——知识点、句子、课文——都可以保存为**知识卡片**。卡片正面是复习的"题面"，背面是这个知识关联的所有上下文。复习按 FSRS 算法调度，让用户在最该复习的时刻回看。

### 12.2 卡片来源

任何实体都可能是卡片来源，**不需要为"复习"重新准备一份内容**——内容就是它在原文里的样子。

| 来源 | 卡片正面 | 卡片背面 |
|---|---|---|
| 知识点（词/语块/句型/语法）| KP 名称 + 中文释义 | 释义 + 出现课文 + 出现例句（带高亮）+ 关联 KP |
| 句子 | 句文本 | 课文出处 + 句中 KP + 跳回原文 |
| 课文 | 课标题 + 场景 | 全文摘要 + 知识总结 + 知识胶囊 + 进入阅读工作台 |

**判断**：
- 不为"复习"单独造内容——卡片的题面直接用原文
- 用户**不需要做整理工作**，保存 = 卡片就有了

### 12.3 保存动作（两种触发）

#### A. 自动保存（轻量）
- 用户在任意视图点击 **⭐ 重点学**（阅读工作台 / 详情卡 / 列表 / 连学 都应支持）= 立即保存为知识卡片
- 这是 §11.5 "用户状态"的延伸

#### B. 显式保存（重一点）
- 在 KP / 句子 / 课文 上有"保存为知识卡片"按钮（区别于 ⭐）
- 用于"我想复习这个但不想标 ⭐"的场景

**两种动作结果一致**：进入卡片库，按 FSRS 调度。

### 12.4 卡片内容（"能回溯"的设计核心）

一张卡片的**完整定义** = 题面 + 一份"上下文档案"。

**上下文档案至少包含**：
- 来源类型（KP / 句子 / 课文）
- 来源 ID
- **所有相关课文**（KP 卡：出现在哪些课）
- **所有相关例句**（KP 卡：原文中出现它的句子，保留原文位置）
- 关联 KP（同课 / 同义 / 反义 / 上层下层）
- 用户原始保存时刻

**关键交互**：在复习时翻到卡片背面，每一条上下文都是**可点击的链接**——点击 = 跳到阅读工作台对应位置，**精确高亮**。

回溯不只是"显示信息"，而是**让用户能立刻回到语境**。复习时卡住，立刻翻原文——这是卡片相比普通闪卡的核心优势。

### 12.5 卡片库（管理界面）

一个独立的入口"我的卡片"（或在主页加一个 mode），提供：

- **总览**：今日到期 / 总卡片数 / 各类型分布
- **筛选**：按类型 / 按来源课 / 按掌握度
- **批量操作**：删除 / 暂停 / 重置进度
- **统计**：保留率、连续打卡、每日复习量

不做花哨的"卡组分组"——25 个能力簇已经提供了天然组织维度，按簇筛选就够。

### 12.6 复习会话（FSRS 调度）

#### 触发
- 应用打开时，若有今日到期卡片，提示"有 N 张待复习"
- 用户主动点击"开始复习"按钮

#### 单卡流程
```
1. 展示正面（题面）
2. 用户尝试回忆
3. 用户主动点"翻面"或按空格
4. 展示背面（上下文档案）
5. 用户自评：
   - Again（完全忘了 / 想错了）
   - Hard（想得很艰难）
   - Good（基本答对）
   - Easy（毫不费力）
6. 系统按 FSRS 算法计算下次到期时间
7. 进入下一张（或会话结束）
```

#### 会话结束
- 显示本次复习数 / 各评级分布 / 距离下次复习的总天数
- 不要强求"今日任务完成"，允许中途退出

### 12.7 FSRS 算法（产品层约束）

实现细节由 AI 决定（参数、初值、公式版本），但**产品行为**必须满足：

#### 卡片状态机
```
新建 ──首次复习──→ 学习期 ──多次成功后──→ 复习期 ──失败后──→ 重新学习期
   ↑                                                  │
   └──────────────── 重置 / 删除 ──────────────────────┘
```

#### 调度原则
- **新卡**：连续多次评 Again / Hard 后，间隔短；评 Good 后进入复习期
- **到期日计算**：基于上次评级的"稳定度"+"难度"+ 目标保留率
- **目标保留率**：可由用户设置（默认 90%），调高 = 更频繁复习，调低 = 拉长间隔
- **失败后**：卡片立刻重新进入学习期，不只是缩短间隔

#### 初值策略
- 用户首次保存 = 新卡，初始稳定度 / 难度取实现者选择的默认值
- 用户在保存时标 ⚠️ 不会（已知薄弱）= 初始稳定度更低、更早到期

#### 评级对状态的影响（产品意图，非公式）
| 评级 | 卡片状态预期变化 |
|---|---|
| Again | 大幅缩短间隔；重新进入学习期 |
| Hard | 间隔略短；不重置状态 |
| Good | 间隔按稳定度正常增长 |
| Easy | 间隔大幅增长；可视为"已掌握"信号 |

### 12.8 与其他功能的关系

- **⭐ 重点学** → 自动保存为卡片（§12.3.A）
- **⚠️ 不会** → 影响卡片初值（§12.7）
- **连学的簇** → 卡片库筛选维度（§12.5）
- **阅读工作台的高亮** → 卡片回溯时的精确上下文（§12.4）
- **搜索** → 卡片库也支持按 KP 名称搜

**重要**：卡片不是独立的产品，而是把已有的"⭐ / 上下文"升级为"可调度复习"。这避免了功能割裂。

### 12.9 不在范围内

- 不做 Anki 导入导出（保持数据本地、纯净）
- 不做云同步
- 不做"卡组共享"
- 不做笔记编辑器（用户可手动编辑卡面内容，但不做富文本）

### 12.10 多设备策略补充

复习功能在手机上要**特别好用**：
- 复习会话应是手机上最重要的入口之一（通勤场景）
- 评级按钮要大（≥ 60px 高）
- 横竖屏都能用
- 翻面动画要快，不要花哨

## 13. 范围

### 在范围内
- 5 个视图的完整功能
- 288 课的全文与所有 KP / 句子
- 25 个能力簇的组织与画像
- 本地用户状态（标星、标弱）
- 课间导航
- 搜索
- **手机 / 平板 / PC 三态可用**（见 §11）
- **知识卡片 + FSRS 复习**（见 §12）

### 不在本规约
- 账号系统 / 云同步（用户状态只本地）
- 语音评测、翻译、笔记、导出
- 编辑/修改内容（应用是只读的）
- Anki 兼容、卡组共享

## 14. 验收标准（产品级，不锁实现）

复刻出来的应用，至少要满足：

1. 打开后能直接看到一个**有意义的节点**（不是空白或随机节点）
2. 任意单击节点能进入详情，详情里**有真实的课文出处**（不是空壳）
3. 5 个视图都能从主页切换，且每个视图**能讲出自己的目的**
4. 搜索能命中中文 KP 名称
5. 连学模式 25 个簇全部可点开
6. 课文共点模式至少展示 50 对
7. 阅读工作台打开一篇课文：
   - 至少 3 种高亮层叠加
   - 范句有视觉标记
   - 单击任一句 → 右栏更新
   - 左栏胶囊点击 → 课文中能定位
8. 桌面 1280×800 下三栏布局清晰；移动端 < 768px 不崩
9. 从主页 KP 详情能跳到阅读工作台对应课文
10. 用户标 ⭐ 后刷新仍保留

## 15. 给实现者的建议（不是约束）

- 数据建模可以**宽**：宁可在原始数据上冗余字段，也不要让前端跑复杂 JOIN
- 关系类操作（"两课的共点 KP"）应该**预先算好**，运行时只读取
- 句子分层（范句 / 长难句 / 例句）的算法可以调，但**总数量级应在 400+300+3000 左右**（不严格）
- 句中 KP 的对齐算法可以选"子串扫描"或"语法对齐"——只要高亮位置不严重错位
- 视图之间不必强求"实时同步"，允许路由式跳转
- 阅读工作台可以是独立页面，不必塞进主页 SPA

这些只是经验，不是规矩。
