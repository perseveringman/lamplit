## B4 暴露的结构性事实：语料只有课文正文

B4 的 233 条搭配候选里，**206 条在 288 课里 0 命中**——包括 `take care of`、`agree with`、`be ready for` 这种最基础的。

原因不是候选不好，是**语料范围**：

| 教材把这些放在哪 | 本语料有没有 |
|---|---|
| 第二册 L22 动词+介词总表 | ❌ 总表在练习部分，不在课文里 |
| 第二册 L70 形容词+介词总表 | ❌ 同上 |
| 第一册 72 个双课练习课 | ❌ 只收了 72 个奇数主课 |
| 课文正文 | ✅ 占 288 课 |

**同一个范围问题在三个地方出现**：B3 的 9 条基础问答句型、B4 的 206 条搭配、第一册的语法骨架判断偏差。
它们不是三个 bug，是一个事实的三个侧面：**本语料是「读物」，不是「教材全册」**。

### 对后续的影响

- **C 组教学点抽取**：教材大纲里的教学点，有相当一部分在本语料里**没有落点**。
  这些必须标成「本课语料无法验证」，而不是从语料里硬推一个替代品。
- **D 组测验**：不能考语料里没有教的搭配。
- **产品定位**：这是一个「精读 + 词汇」工具，**不是教材替代品**。用户如果指望它覆盖教材的语法操练，
  会失望。这句话应该出现在产品说明里。

## C 组进展 · C1 启动 + 第一个 C2 发现

### C1 采信：第一册教材事实表已建立并交叉验证

来源：新东方《第一册时态递进表》× protogenesis NCE1.md 逐课笔记，**21 项全部一致**。

### C2 验证：闸门第一次就抓出一个真实缺陷

拿教材事实去核对语料证据，10 条里 **1 条对不上**：

```
官方 L83 → b1-042「Going on a holiday」教现在完成时
课文原文：「I've already had lunch.」「I've just had a cup.」
规则命中：0
```

追下去发现 `g-present-perfect` 的过去分词是一份**手写的 ~50 词白名单**，`had` 根本不在里面。三个连带缺陷：

| 缺陷 | 后果 |
|---|---|
| 白名单只有 50 个分词 | 规则动词的 `-ed` 形式**一个都识别不了** |
| `have/has` 与分词之间不允许主语 | **现在完成时的疑问句全部漏掉**（"Have you had lunch?"） |
| 反推分词时"去掉原形" | `become` / `come` / `run` 这类**原形即分词**的动词被误删 |

修法：从 `VERB_FORMS` 反推分词集（去掉原形、`-ing`、三单、ECDICT 垃圾形式，剩下的就是过去式/过去分词）+ 规则动词 `-ed` 放行 + `come` 型补充表 + 允许问句主语。

结果：`g-present-perfect` 379 → **394 次 / 164 课**，第一册教材事实与语料证据**吻合度 10/10**。

### 附带发现：同一个转义坑犯了两次

JS 字符串字面量里 `'\s+'` 写成 `'\s+'` 会退化成 `s+`。这次在 `subject` 上重演（上一次是 `BE_GAP`）。
已加扫描：编译后的正则里若出现 `[)(|]s+`，即为转义丢失——当前**零残留**（规则与语块全部扫过）。

## 附：本轮反复踩到同一类编辑陷阱

多行规则用「替换首行」的方式改，会留下**孤儿正则行**——三次都这样，其中一次还删错了行（删掉新正则留下旧的）。

**根因**：`rule(...)` 调用跨两行，`s.index('\n', i)` 只切掉第一行
**正确做法**：找到规则起始行后，**收集紧随其后的所有裸正则行（以 `/` 开头）**，整体替换，而不是假设只有一行

## 倒装规则族（B 组返工）

C1 第三轮发现 11 条缺口里 **倒装占 4 条**，是最大的一族。原来一条 `g-inversion-negative` 只覆盖"否定词置句首"。

拆成三条：

| 规则 | 覆盖 | 命中 |
|---|---|---|
| `g-inversion-negative` | 否定词置句首（Never / Rarely / Seldom / Hardly / No sooner / Not only / Not until / Little / Nowhere） | 6 次 / 6 课 |
| `g-inversion-only` | only + 状语置句首（when / after / then / if / by / in / with / through / because） | 3 次 / 3 课 |
| `g-inversion-locative` | 地点或方向状语前置引起的完全倒装 | 4 次 / 4 课 |

### 地点倒装这条规则值得记一笔

**第一版精度极差**：`地点状语 + 动词` 这个结构，96 条匹配抽样 6 条**全是假的**：

```
In the morning, Mrs Sawyer goes to work        ← 不是倒装
In return for this, the beggar stood on his head ← 不是倒装
On Wednesday evening, we went to the Town Hall   ← 不是倒装
```

**完全倒装的真正判据是「动词之后紧跟主语」**（`flowed a great river` / `stood a small chapel`）。加上这个约束后：

```
96 次 → 4 次，精度 100%（抽样全部为真倒装）
```

**这是一次典型的「用结构约束换精度」，代价是召回也降下来了。** 规则现在**精确但漏得多**——好过**宽泛但半数错**，因为错标的语法点会污染 `teachingFocus` 和出题。

### 顺带修掉的两处 parent 悬空

- `p-no-sooner` 的 parent 指向**已删除**的 `g-inversion`（早先合并时漏改）
- `p-only-when` 的 parent 改指新建的 `g-inversion-only`

## E 组完成：进度数据层

### E1 · UserData v1 → v2（显式迁移）

```ts
lessons: Record<lessonId, {
  state: 'reading' | 'read';
  firstReadAt: number;   // 0 = 迁移前就在读，具体时间未知
  lastReadAt: number;
  readCount: number;
  visited?: string[];    // 累计看过的句子 id
}>
```

迁移的两条纪律：

- **不伪造历史**。迁移时 `lessons` 从空开始，`firstReadAt` 一律 0。
  拿 `lastReadAt` 或当前时间冒充，会让"连续天数"和"开始日期"当天就是错的。
- **保留拒绝未知版本的安全语义**。`normalize()` 对 `version !== 2` 仍然抛错、不覆盖原数据。

**顺带修掉一个真实漏洞**：`typeof null === 'object'`，所以 `cards: null` 能通过原来的结构校验。
加了显式 null 检查。

### E2 · `src/lib/progress.ts` 三条轴

```
覆盖  有阅读记录的课 / 总课数          （lastReadAt > 0 才算，迁移来的 0 不计）
沉淀  卡片数 · 已进入复习期 · 已成熟   （stability >= 21，沿用 Anki 约定）
掌握  复习期内回忆成功率              （只数 previousState === 'review'）
```

**三条轴刻意不做成一个复合百分比**：不同步本身是信息——
「覆盖高 / 沉淀低」= 读得多但没留下东西；「覆盖低 / 掌握高」= 反复磨少数几课。

两个口径决定：
- 掌握率**只统计进入复习期之后的回忆**。学习期的回忆必然成功率高（刚看过），混进来会整体抬高。
- 没有复习记录时掌握率是 **`null` 而不是 0**。"没数据"和"全错"不是一回事。

### E3 · Reader 累计可见句

`readPosition` 现在同时写入 `lessons[lessonId]`。**用累计集合而不是"读到第几句"**——
读者会回看、会跳读，只记最后一句会低估覆盖。`readCount` 只在换课时 +1。

### E4 · 连续天数改口径

旧实现只统计 `reviews` 的日期，**只读课文不复习的日子不算数**——于是"每天都打开来读"的用户
会看到连续天数断掉。现在 `streakOf` 把阅读记录一并计入，并且当天未结束不算断。

## 词汇题空缺已补：新判据「本课重复出现 >= 2 次」

D2 完成时题库 **99% 是结构辨认**（691 结构 / 5 填空），因为 `focus` 只有 3 条且多为语法句型，
而"填空选释义"只能用于词和语块。**对一个自称「精读 + 词汇」的工具，词汇一侧是空的。**

### 修法：加第二判据，而不是放松 ⑤

```
⑤ 命中该课 teachingFocus
   或
   命中本课「重复出现 >= 2 次的内容词」判据
```

判据的完整定义（`vocabIdsOf`）：

```
在本课命中 >= 2 次          ← "这一课有意在用它"的可测代理
且不是功能词（复用 stop 表）  ← 排除 the / of / is 这类
且有释义（coreSense/meaning）
且引入册不超前
按命中次数取前 4 个
```

**为什么加判据而不是放松 ⑤**：放松 ⑤ 会让题库退回到"考文本里恰好出现的结构"——
那正是整个 D 组要避免的。加判据是**提出一个新的、可测的、可辩护的信号**。

### 结果

```
696 → 1720 题
覆盖 268 → 288 课（全部）
题型  { structure: 691, blank: 1029 }
```

### 一个设计决定：判据在校验侧独立重算

`data:check` 不采信题目自己的标记，而是**用同一个 `vocabIdsOf` 重新算一遍**
（`validateItem(q, l, kpById, pool, foc, vocabIdsOf(l, foc, kpById, stop, l.book))`）。

**否则校验只是自证**——题目说"我符合判据"，校验点头，等于没校验。

### 断言抓到的一件事

上线后报 **2 题选项重复**：两个不同知识点有相同的释义字符串，
