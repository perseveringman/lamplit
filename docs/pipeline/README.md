# 语料 → 语境释义：可复用流水线

这套流程把**任意英文课文语料**加工成一个「可点可查、释义绑定语境」的学习数据集。
它在新概念英语 1–4（288 课 / 65,944 词）上跑通并被验收，本文记录**与语料无关的那部分**。

> **当前状态**：流程的 7 个阶段里有 5 个已经完全与语料解耦；剩下 2 个（语料接入、编辑层）
> 仍通过硬编码绑定新概念。解耦方案见 [CORPUS-ADAPTER.md](CORPUS-ADAPTER.md)。

---

## 一、流水线总览

```
┌─ 0 语料接入 ────────────────────────────────────────────┐
│  原始文本 → lessons[] + sentences[]（带来源偏移）        │  ⚠️ 仍与语料耦合
└─────────────────────────────────────────────────────────┘
                          ↓
┌─ 1 词典层 ──────────────────────────────────────────────┐
│  ECDICT(812MB) → 语料用到的那部分 → corpus-dict.json(4.5MB)│  ✅ 通用
└─────────────────────────────────────────────────────────┘
                          ↓
┌─ 2 词形层 ──────────────────────────────────────────────┐
│  词典 exchange → 动词变形表 → verb-forms.mjs（提交）      │  ✅ 通用
└─────────────────────────────────────────────────────────┘
                          ↓
┌─ 3 标注层 ──────────────────────────────────────────────┐
│  语法规则 + 语块清单 × 语料 → hits[]（精确字符区间）      │  ✅ 通用（规则表需调）
└─────────────────────────────────────────────────────────┘
                          ↓
┌─ 4 语块验证 ────────────────────────────────────────────┐
│  候选池 × 语料 → 存活的语块清单（零死条目）              │  ✅ 通用
└─────────────────────────────────────────────────────────┘
                          ↓
┌─ 5 语境释义（机械层）───────────────────────────────────┐
│  词典义项 × 每次出现 → 词性过滤 + 语块覆盖 + 原形回退     │  ✅ 通用
└─────────────────────────────────────────────────────────┘
                          ↓
┌─ 6 LLM 增强 ────────────────────────────────────────────┐
│  机械层剩余 → 批量标注 → 机械校验 → 覆盖层                │  ✅ 通用
└─────────────────────────────────────────────────────────┘
                          ↓
┌─ 7 金标集 + 产出 ───────────────────────────────────────┐
│  回归夹具 → public/data/（catalog + books + contexts）   │  ✅ 通用
└─────────────────────────────────────────────────────────┘
```

## 二、各阶段的契约

### 0 · 语料接入

| | |
|---|---|
| **输入** | 一个目录，内含原始文本文件（Markdown / 纯文本） |
| **输出** | `lessons[]`，每课含 `id / book / no / label / title / sourceFile / sourceLine / blocks[]` |
| **关键约束** | **句子的每一个字符都必须能回溯到源文件的精确位置**（`sourceBlock + sourceStart`） |
| **验证** | 每句都能从 `sourceBlock.slice(sourceStart, +len)` 精确还原 |
| **可否跳过** | 否 |

这一段的设计原则是「**不补写**」：源文的残缺（标题与首句粘连、拼写错误、截断）原样保留并标注，
而不是用模型猜一个通顺版本。理由见 [PRINCIPLES.md](PRINCIPLES.md) 原则 7。

### 1 · 词典层

| | |
|---|---|
| **输入** | 语料里出现过的所有词形 |
| **输出** | `.dict-cache/corpus-dict.json` —— 只含用到的词条，约 4.5MB |
| **实现** | [`ecdict.mjs`](../../scripts/ecdict.mjs) + [`build-dict-cache.mjs`](../../scripts/build-dict-cache.mjs) |
| **命令** | `npm run dict:fetch` → `npm run dict:cache` |
| **验证** | 词条命中率（新概念上 **98.7%**，未命中的全是源文残缺与专名） |
| **可否跳过** | 是（跳过后释义退回词级，覆盖率大幅下降） |

`ecdict.mjs` 被刻意写成**纯函数**（`parseEntry` / `parseExchange` / `parsePosRatio` 不碰数据库），
所以单元测试不需要 812MB 的库文件。

**三个必须处理的 ECDICT 特性**：

1. `translation` 是**按词性分组的整体**，一行里可能压着九个义项
   （`play` 的 `n.` = 游戏, 游玩, 玩笑, 运动, 比赛, 赌博, 跳动, 表演, 剧本）
2. 义项顺序**本身就是「常用度排序」**，按词性重排会破坏它
3. 屈折形式有自己的词条，而那条常常是**同形异义词**
   （`pictures` = 电影院、`books` = 书评）——用 `frq` 词频排名当裁判

### 2 · 词形层

| | |
|---|---|
| **输入** | 词典缓存 + 语块清单里的动词首词 |
| **输出** | [`verb-forms.mjs`](../../scripts/verb-forms.mjs)（**提交进版本库**） |
| **验证** | 覆盖率（新概念上 174 个动词） |
| **可否跳过** | 否（语块匹配依赖它） |

**为什么必须固化成提交产物**：词典缓存 824MB 不进版本库，新克隆的仓库没有 ECDICT。
而语块匹配依赖变形表——所以由词典**生成一次**，把结果提交。

**ECDICT 的变形表有三处坑**（都已在代码里处理）：

- `be` 的表是 `["being","was","been","is","bes"]` —— **缺 `am`/`are`/`were`/`be`**
- 有些短语条目的 `lemma` 被误标成动词，垃圾形如 `of--the` 会作为 `have` 的变形混进来
- 语料里只有 `taught` 而没有 `teach` 时，按原形查表会查空

### 3 · 标注层

| | |
|---|---|
| **输入** | `sentences[]` + 语法规则表 + 语块清单 + 词典 |
| **输出** | 每句的 `hits[]` = `[kpId, start, end, glossIndex?, methodIndex?]` |
| **验证** | 位置合法性、正反索引一致、`end > start`、区间不越界 |
| **可否跳过** | 否 |

**位置用 UTF-16 code unit**，与 `String.slice` 一致——这样前端不需要任何转换就能高亮。

**四类知识点**：`word` / `chunk` / `pattern` / `grammar`。
它们的**释义单元不同**，这一点贯穿整个流程：

- `word` —— 义项依赖语境，需要消歧（本流程的主要工作）
- `chunk` —— 整体一个意思，**并且会覆盖包含在它内部的词**
- `pattern` / `grammar` —— 结构标注，**不参与释义选择**

> ⚠️ 一个踩过的坑：把 `grammar`/`pattern` 的区间也当作「覆盖」会得到虚高的数字。
> 语法命中经常横跨整句（`'handbag' ⊂ 一般疑问句 'Is this your handbag?'`），
> 那不是语义单元。**只有 chunk 是紧致的语义单元，可以用作覆盖信号。**

### 4 · 语块验证

| | |
|---|---|
| **输入** | 候选池（人工按类别枚举）+ 语料 |
| **输出** | 存活的语块清单 —— 每一条都**真的在语料里出现过** |
| **实现** | [`verify-chunks.mjs`](../../scripts/verify-chunks.mjs) |
| **命令** | `npm run chunks:verify` |
| **验证** | **死条目数为 0**，这是硬断言 |
| **可否跳过** | 否 |

**方法论**：候选来自类别枚举（短语动词 / 介词短语 / 习语 / 功能套语 / 半固定框架 /
`be+形容词+介词` / 动词+介词），**语料只做验证**。

反向挖掘（从语料挖语块）试过四种方法，全部失败，原因见 [PRINCIPLES.md](PRINCIPLES.md) 原则 4。

**匹配器必须处理的三种形态**（每一条都曾造成成批的假死条目）：

| 形态 | 例子 | 处理 |
|---|---|---|
| 屈折变化 | `wake up` ← `woke up` | 用变形表展成正则分支 |
| 中间夹副词 | `be proud of` ← `am **very** proud of` | `be` 后留可选副词槽 |
| 占位符 | `at one's best` ← `at **my** best` | 展开 `one's`/`sb`/`sth`/`oneself` |

**最关键的一条纪律**：验证器**必须 import 发货的那张变形表**，不能自己现算一张。
自己现算会出现「验证通过、线上匹配不到」的假绿——这个坑真实发生过，
由 `data:check` 的死条目断言抓出来。

### 5 · 语境释义（机械层）

| | |
|---|---|
| **输入** | 词典条目 × 每次出现（句子文本 + 起止位置 + 是否被语块覆盖） |
| **输出** | 每次出现一个 `{zh, en, pos, method}` |
| **实现** | [`senses.mjs`](../../scripts/senses.mjs) |
| **命令** | `npm run report:senses` |
| **验证** | 覆盖率（新概念上 **99.6%**）与方法分布 |
| **可否跳过** | 否 |

**优先级链**（写进代码，不是写在文档里）：

```
原文旁注  >  语块  >  LLM 语境判定  >  编辑词表单义  >  词典首义
   ↓          ↓           ↓                ↓              ↓
 出现级    语义单元    出现级          词级           词级
```

每一步的取舍理由：

- **原文旁注最先** —— 它是唯一的「出现级人工证据」
- **语块次之** —— 词在语块里时，词义由语块承担（`on the left` 里的 `left` 不是「离开」）
- **编辑词表的「单义」条目**高于词典 —— 人工整理且只有一个意思，可靠
  （`friends | 朋友（复数）`、`ice | 冰`）
- **编辑词表的「多义」条目**低于词典 —— 它正是要修的问题形态（`play | 戏剧；玩；演奏`）

**决定用「词形自身词条」还是「原形词条」的规则**：

```
自身没有中文义项             → 用原形（went → go、men → man、told → tell）
自身没有词频排名(frq=0)      → 是附带收录的变体，用原形（pictures → picture）
两边都有排名                 → 取更常用的那个（left 排名好，保留「左边的」）
```

### 6 · LLM 增强

| | |
|---|---|
| **输入** | 机械层无法确定的部分 |
| **输出** | `.llm/overrides.json`（**提交进版本库**）—— `{senses: {...}, analyses: {...}}` |
| **实现** | [`llm-prepare.mjs`](../../scripts/llm-prepare.mjs) → 批量标注 → [`llm-merge.mjs`](../../scripts/llm-merge.mjs) |
| **命令** | `npm run llm:prepare` → （批量）→ `npm run llm:merge` |
| **验证** | 机械校验 + 拒绝率（新概念上 **零拒绝**） |
| **可否跳过** | 是（跳过后退回机械层结果） |

**核心设计：这不是运行时依赖，是构建期一次性投入。** 结果落成静态 JSON，
运行时零延迟、可离线、可 diff、可审查。

**批次走文件而不是脚本参数**：一个批次的上下文写进 `.llm/in/<id>.json`，
agent 读它、写 `.llm/out/<id>.json`。这样脚本参数保持很小，且批次可重跑。

**两类任务的约束方式不同：**

**词义任务有候选集，所以约束在候选集内选择：**

```
输入：句子 + 目标词 + 词典给的候选义项数组
输出：只返回下标 index（+ 选中的中文）
```

这样得到的是**可枚举、可校验**的结果，而不是一段无法验证的文本。

**句子任务没有候选集，所以改用三条机械可验证约束：**

| 约束 | 作用 |
|---|---|
| `skeleton` / `modifiers[].text` 必须是原句的**精确子串** | 模型编不出来（和 hit 偏移是同一个技巧） |
| `modifiers[].role` 必须在**封闭词表**内 | UI 才不会长出三十种说法 |
| `grammarRefs` 必须是该句**已有语法点的子集** | 不许自己发明语法点 |

**违反约束的条目整条丢弃**，不是将错就错。新概念上的结果是 815/816 通过，
唯一被丢的那条是因为 `whyLearn` 超过长度上限。

### 7 · 金标集 + 产出

| | |
|---|---|
| **输入** | 全部中间产物 |
| **输出** | `public/data/`（catalog + books + contexts + pairs + sentences） |
| **实现** | [`check-data.mjs`](../../scripts/check-data.mjs) + [`sense-quality.test.ts`](../../tests/sense-quality.test.ts) |
| **命令** | `npm run data:check && npm test` |
| **验证** | 见下表 |
| **可否跳过** | 否 |

**金标集是回归夹具，不是质量证明。** 它冻结手工判定过的用例，防止重跑时退化：

```json
{
  "id": "left-in-on-the-left",
  "sentenceId": "b1-013-s008",
  "kpId": "w-left",
  "text": "It is on the left.",
  "expect": ["左"],
  "notExpect": ["离开", "留下"],
  "note": "旧实现给的是「leave 的过去式；离开；留下」——完全不属于这个语境。"
}
```

- `expect` 是**可接受答案集合**，命中任一即可（避免把措辞差异当错误）
- `notExpect` 抓的是「**错得离谱**」而不是「不够精确」——这类错误对学习者伤害最大
- 标了 `knownGap` 的条目会被记录但**不阻塞构建**：它是已知的、有明确修复路径的缺口

## 四、命令速查

```sh
# 一次性准备
npm run dict:fetch        # 下载 ECDICT（约 207MB → 解压 812MB）
npm run dict:cache        # 抽取语料用到的词条（4.5MB）

# 内容流水线
npm run chunks:verify     # 验证语块候选：必须真的在语料里出现
npm run chunks:forms      # 从词典生成动词变形表
npm run data:build        # 重建全部语料产物
npm run report:senses     # 打印覆盖率、方法分布、A/B/C/D 分层

# LLM 增强（可选）
npm run llm:prepare       # 切分批次
#   → 批量标注写 .llm/out/
npm run llm:merge         # 合并 + 机械校验 → .llm/overrides.json

# 验收
npm run data:check        # 数据断言（含死条目与语块覆盖率两项指标）
npm test                  # 领域 + 单元 + 金标
npm run build             # tsc -b + vite build
npm run test:e2e          # 真实浏览器（真实 G6 + 真实 IndexedDB）
```
